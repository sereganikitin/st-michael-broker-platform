# Атрибуция брокеров, агентств, фиксаций и сделок

## Источники истины

- Текущее членство брокера в агентстве: `BrokerAgency`.
- Неизменяемая компания конкретной фиксации: `Client.fixationAgencyId`.
- Компания конкретной сделки: `Deal.agencyId`.
- Аудит происхождения и изменений членства: `BrokerAgencyEvent`.
- amoCRM хранит только одну операционную компанию контакта — текущее
  `BrokerAgency.isPrimary`. amoCRM не является источником полной истории
  нескольких агентств.

## Правила

1. У брокера может быть несколько одновременных активных агентств.
2. Активным считается `BrokerAgency.endedAt = null`.
3. У брокера может быть не более одного активного основного агентства.
4. Новая фиксация никогда автоматически не завершает другие связи.
5. При фиксации выбирается одно активное агентство подающего заявку брокера.
6. Если заявка подана на другого брокера, выбранное агентство:
   - навсегда записывается в `Client.fixationAgencyId`;
   - добавляется этому ответственному брокеру как дополнительная активная
     связь или подтверждает уже существующую;
   - не становится основным, если у ответственного брокера уже есть primary;
   - не удаляет и не завершает другие агентства ответственного брокера.
7. При самостоятельной фиксации брокер с несколькими агентствами явно выбирает
   компанию. По умолчанию в форме выбрано основное агентство.
8. Повторная фиксация через ранее завершённое агентство реактивирует только эту
   связь и открывает новый текущий период; предыдущие периоды остаются в
   `BrokerAgencyEvent`.
9. Смена primary только меняет основную компанию для amoCRM. Она не означает
   увольнение из предыдущего агентства.
10. `endedAt` ставится только отдельным явным действием. Основную связь нельзя
    завершить, пока другое агентство не назначено основным.
11. Сделка, созданная из фиксации в кабинете, наследует
    `Client.fixationAgencyId`. Текущий primary используется только для старых
    записей без атрибуции.

## Как считать статистику

- Число фиксаций брокера по агентству: считать `Client` по эффективному
  брокеру `COALESCE(responsibleBrokerId, brokerId)` и
  `fixationAgencyId`.
- Продажи и суммы: считать по `Deal.brokerId + Deal.agencyId`; статус и дата
  ДДУ определяются отдельной подтверждённой логикой сделок.
- Текущее место работы нельзя восстанавливать из последней фиксации. Для этого
  используется только активный `BrokerAgency`.
- Исторический переход нельзя выводить из смены amoCRM Company. Используются
  `joinedAt`, `endedAt` и события `LINK_CREATED`, `LINK_REACTIVATED`,
  `LINK_CONFIRMED`, `PRIMARY_CHANGED`, `LINK_ENDED`,
  `FIXATION_ATTRIBUTED`.

## Пример

Координатор агентства «Альфа» фиксирует клиента на брокера Ивана, затем
координатор «Беты» фиксирует другого клиента на того же Ивана:

- у Ивана активны связи «Альфа» и «Бета»;
- первая заявка считается за «Альфой», вторая — за «Бетой»;
- прежняя связь не получает `endedAt`;
- в amoCRM у Ивана остаётся только его выбранное основное агентство;
- если Иван позже сам фиксирует клиента, он выбирает «Альфу» или «Бету», и
  выбранная компания сохраняется у этой заявки навсегда.
