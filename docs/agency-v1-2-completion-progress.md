# Полное ТЗ «Агентства v1/2»: продолжение реализации

Источник требований: PDF `agency-v1-2-call-center-proposal-2026-10-26.pdf`, страницы 2–5.
Полная рабочая матрица сверки хранится в `../output/agency-v1-2-completion-checklist.md` относительно корневой папки проекта, вне данного checkout.

## 27.10.2026 — первая итерация

Подтверждённые недостатки опубликованного рабочего места:

- Очередь показывала «Нет телефона», даже если у агентства есть активное проверенное контактное лицо.
- Снимок фильтра содержал агентство и тип, но восстановление игнорировало их.
- Сериализация даты следующего шага и срока скрипта могла дописать секунды повторно.
- Короткая очередь не показывала приоритет источника и причину назначения.

Исправлено локально в ветке `feat/agency-v1-2-completion-20261027`. Номера выбираются только из кабинета и активных контактных лиц; исторические телефоны автоматически действующими не считаются. Различающиеся приоритеты периодов показаны вместе как приоритеты источника, не подменены придуманным текущим значением.

Проверки: 185 frontend-тестов, TypeScript без ошибок, Chromium на localhost с перехватом всех API и искусственными данными — сохранение контакта, его телефон в очереди и повторное открытие формы.

Production этой итерацией не изменён. Это не подтверждение готовности всего ТЗ.

## Следующие обязательные участки

### 27.10.2026 — ручная проверка качества (локально)

В журнал попыток добавлена ручная проверка конкретной неизменяемой записи: актуальность предложения, выявление потребности, фиксация договорённости и следующий шаг. Значение по умолчанию — «Недостаточно данных»: без аудио нельзя считать содержание разговора подтверждённым. Автоматического рейтинга сотрудников нет.

Сервер требует `READ_ALL` и отдельное `CALL_REVIEW` для записи. Просмотр — только `READ_ALL`. Новая миграция добавляет таблицу и разрешение, но никому его не выдаёт. Исправления добавляют новую версию с обязательной причиной; предыдущая версия и автор сохраняются. Повторная отправка идемпотентна, блокировка попытки и ожидаемая версия защищают от параллельной перезаписи. Проверка старой исправленной попытки явно относится к старой версии.

Проверки этой итерации:

- 47 целевых API-тестов (включая 10 новых QA-тестов), 185 frontend-тестов;
- TypeScript web и API build-config, валидация Prisma;
- 82 проверки настоящего HTTP/JWT API на отдельной локальной PostgreSQL, в том числе права, чужая карточка, повторная отправка, конфликт и история;
- SQL миграции на отдельной пустой PostgreSQL БД: сохранность исходных строк, уникальные версии/отправки, запрет удаления проверенной попытки;
- Chromium localhost: сохранение, обязательная причина исправления, история после reload, отсутствие формы без `CALL_REVIEW`.

Не выполнено этой итерацией: публикация, общая защита несохранённых черновиков (включая QA), отдельный экран руководителя и сверка всего ТЗ. Проверка UI использовала искусственные API-ответы; настоящие HTTP/БД сценарии проверены отдельно. Реальные пользователи, звонки и права production не менялись.

1. Несохранённые черновики контактов, результата и скрипта: предупреждения, переключение карточек, потеря данных при фильтрах и навигации.
2. Отдельный экран руководителя, причины и длительность просрочки, показатели качества и расшифровки.
3. Включить ручную проверку качества в отдельный экран руководителя и сквозную приёмку; её сервер и форма добавлены локально выше.
4. Проверка существующих связей Mango/amoCRM и подготовка подтверждённой аналитики без подмены ручной отметки фактом интеграции.
5. Повторная изолированная проверка полного цикла и прав. Реальные два оператора, выборка пилота, условия скрипта, сроки повторов и включение телефонии требуют конкретных согласованных значений; их не назначать автоматически.
6. Общий аудит требований, безопасная публикация через PR, exact-SHA CI/backup/rehearsal и финальная приёмка.

### 27.10.2026 — сохранность черновиков (локально)

Результат звонка, контакт, исправление результата, ручная QA-проверка и скрипт теперь сохраняют черновики в sessionStorage текущей вкладки, раздельно по пользователю и форме/агентству. Данные не отправляются в API автоматически. Баннер показывает наличие несохранённых форм; при недоступном хранилище явно предупреждает, что остаётся только копия в памяти.

Смена карточки/поиска/фильтра не стирает ввод; возврат и reload восстанавливают его. Переход по ссылке и Back/Forward в Chromium требуют подтверждения. В браузерах без Navigation API переход Back может не блокироваться, но данные остаются в хранилище вкладки. Есть явная отмена с подтверждением. Успешное сохранение очищает соответствующий черновик; ошибка оставляет ввод. В контакте, скрипте и QA хранится исходная версия для обнаружения чужих изменений после возврата. Поля блокируются во время отправки, чтобы не стереть новый ввод успешным ответом на предыдущий запрос.

Проверено на localhost в настоящем Chromium с искусственными API: все пять форм, смена агентства, отмена перехода по ссылке/Back, reload, конфликт сохранения контакта и явный отказ от черновика. Отдельно сохранены зелёными сценарии сохранения контакта/дат и QA-истории. Unit-проверки охватывают разделение пользователей, восстановление, очистку, повреждённое/недоступное хранилище.

Это не публикация. Общий экран руководителя, итоговые сценарии и полный аудит ТЗ ещё впереди; черновик выбора пилота и экран кампаний требуют отдельной проверки.

### 27.10.2026 — отдельный экран руководителя (локально)

Добавлен маршрут `/admin/agencies-v1-2/supervisor` и ссылки из меню/рабочего места. Сервер требует `READ_ALL`, а запись причины просрочки — также `CALL_ASSIGN`. Права в действующей базе не менялись.

- Период по МСК, сотрудник, кампания, агентство и тип; фильтры применяются явно. При ошибке остаётся подписанная последняя успешная выборка. Сохранённые общие представления и экспорт событий используют применённый фильтр.
- Охват, ручная отметка разговора, договорённости и выполнение задач: формулы, числитель/знаменатель и переходы к исходным событиям. Исправление относится ко времени исходного звонка. Нулевой знаменатель остаётся неизвестной долей, а не нулевой эффективностью.
- Открытые просрочки показываются на единый момент расчёта, отдельно от событий выбранного периода. Есть длительность, ответственный, ручная причина и история её изменения. Причина хранится в существующем append-only аудите; версия задачи и ключ отправки защищают от конфликтов/повторов. Новая схема БД для причин не нужна.
- Состав текущей нагрузки по типам и проблемам контактов не подменяется рейтингом сотрудников. Фильтр прежнего оператора после переназначения не включает текущую чужую нагрузку.
- Качество данных и выборочная ручная QA-проверка имеют расшифровки. Проверка старой версии не считается проверкой исправленного результата. Переход к карточке сохраняет точный ID агентства.
- Спорные сопоставления источника отделены от новых строк без карточки; прежний общий счётчик больше не подписывается как число только спорных совпадений.

Проверки: 46 целевых API-тестов, 188 web-тестов, TypeScript обоих приложений; 101 проверка настоящих PostgreSQL+HTTP/JWT; Chromium с искусственными данными — экран, фильтры, ссылки, причины/история, доступ, QA и регрессии черновиков. Просмотрен снимок вёрстки, фильтры уплотнены для рабочего экрана. Production не менялся.

Остаются полный сквозной аудит матрицы ТЗ, пилот/кампании, проверка имеющихся Mango/CRM связей, сопоставимость подтверждённых итогов кампаний и безопасная публикация. Данные интеграций не заменены ручными отметками или нулями.

### 27.10.2026 — оставшиеся детали очереди и синхронизации

Добавлены наборы полей очереди и их сохранение в личном/общем представлении; название и DNC не скрываются. Закреплены заголовок очереди и название карточки. Проверено браузером вместе с восстановлением фильтра.

Инцидент синхронизации теперь может храниться как pending до 09:00 МСК. Отправка атомарно резервируется до обращения к сервису уведомлений; неопределённый ответ не вызывает повторную рассылку. Ночные инциденты, устранённые до утра, не отправляются. Старые ISO-резервации считаются уже отправленными. 12 тестов проходят без реальных уведомлений.

Расширенный изолированный HTTP+PostgreSQL сценарий прогоняет настоящий `PartnerSheetService` с искусственным reader и перестановкой строк. 107 проверок подтверждают сохранность контактов/истории/задач/назначений. 42 теста source pipeline также проходят.

Живая матрица дальнейшей приёмки — `docs/agency-v1-2-requirements-audit-20261027.md`. Пользователь указал действующих менеджеров КЦ как исполнителей; новый состав или расширение прав не назначались.

Автоматический дозвон и запись разговоров PDF отдельно ограничивает согласованием. Автоматические длительности SLA не заданы: не изобретать их. Исходные Google-вкладки «Контакты»/«Обзвон БТ», права, коммерческие условия и данные CRM не менять ради демонстрации готовности.
