# Агентства v1/2: критический аудит 27.10.2026

Проверена реализация `e979c9c` против пяти страниц согласуемого PDF и
canonical `origin/master` (`5d71831`). Содержимое базы `a637a86` совпадало
с этим master; история master включена локальным merge. Публикации не было.

## Найденные ошибки и исправления

| Проблема | Исправление и доказательство |
|---|---|
| Пилот не создавался для сопоставленных агентств без сделок: общий список отбрасывал low-signal записи | Подготовка использует тот же канонический resolver, что создание кампании, с явным `includeLowSignal`. Реальный POST пилота, повтор запроса и активация проверены через PostgreSQL/HTTP |
| После переназначения история могла попасть в показатели нового оператора | Назначение больше не меняет владельца: закрывается старое и создаётся преемник. Для старых изменяемых записей учитывается автор первоначальной попытки, включая цепочку исправлений. Проверены оба оператора и исправление администратором |
| Новый исполнитель терял контекст прежних разговоров | История подготовки карточки загружается отдельно от статистики автора. Видимость прежнего разговора не приписывает его новому исполнителю |
| Исправление старого разговора могло менять уже переданную задачу | Изменение следующего шага запрещено прежнему исполнителю, если связанная задача передана другому сотруднику. Реальный HTTP возвращает 403, задача остаётся прежней |
| Новые обязательные поля затронули старые кампании | Строгая проверка ограничена маркером `agencyWorkspace`; старый SEND_INFORMATION без следующего шага по-прежнему записывается. Проверено реальным HTTP |
| Любая попытка автоматически завершала обещанные задачи | Автозавершение удалено. Задача завершается только явным действием. NO_ANSWER оставляет обещание OPEN. Добавлен тип CALL / SEND_MATERIALS / MEETING / OTHER; возобновлять звонок можно только из CALL |
| Claim использовал владельца, прочитанного до ожидания блокировки | После `FOR UPDATE` назначение читается снова. В тесте удерживается реальная блокировка PostgreSQL, владелец меняется, ожидающий claim получает отказ |
| Контакты проверяли владельца до транзакции | Проверка владения повторяется под блокировкой Agency внутри транзакции, совместно с optimistic version |
| Две одновременные одинаковые отправки могли дать конфликт вместо идемпотентного результата | После конкурирующего version conflict сервер проверяет квитанцию submissionId и возвращает совпадающий результат. Два параллельных HTTP POST создают одну попытку |
| Не хватало фильтра типа и агентства, долей и качества данных | Серверные фильтры, устойчивые списки вариантов, явные числители/знаменатели, детализация, качество данных и текущая загрузка. Нулевой знаменатель не отображается как достоверный нулевой процент |
| Неоднозначная доступность формы исправления | Явные aria-label для комментария и причины; реальный браузер записывает исправление и проверяет его в PostgreSQL |
| Ссылка на исходную таблицу вела оператора без READ_ALL в отказ | Ссылка скрыта без разрешения; промежуточный breadcrumb не является ссылкой. Администратор открывает таблицу и выгружает CSV |
| Возможны пустые tel-ссылки из некорректного телефона | Ссылка доступна только при достаточном количестве цифр; новые контакты с одним форматированием без цифр отвергаются |

## Что проверялось без mock бизнес-операций

Создан отдельный PostgreSQL 16 cluster, привязанный только к 127.0.0.1:55439.
Тестовая БД изначально получила полную схему canonical master; затем применены
обе настоящие миграции. Prisma Client сгенерирован отдельно в `work/`;
существующий checkout и его зависимости не менялись. `prisma migrate diff`
не обнаружил различий между результатом миграций и схемой кода.

`apps/api/test/agency-workspace.postgres.ts`: 67 проверок через настоящий
Nest HTTP, JWT/roles, сервисы workflow и Prisma. Доставка SMS, внешние очереди,
Google, Mango и amoCRM не запускаются. Для аутентификации используется настоящий
JwtStrategy с чтением тестовых Broker; исходная таблица предоставляется
PartnerSheetService из его проверенного локального cache. Бизнес-записи,
транзакции и права не подменяются mock-функциями.

`scripts/test-agency-workspace-live.cjs`: 22 сценария в браузере против
production standalone web-сборки и этого API, без перехвата API-ответов:
тип / агентство / оператор / кампания / период / поиск, CSV, личный фильтр,
claim и вторая вкладка, создание контакта, результат, исправление, явное
выполнение задачи, сохранение/удаление представления, утверждение скрипта,
подготовка/активация/архив кампании, исходная таблица и её CSV.
Вызов tel-ссылки не производится: проверяется доступность без реального звонка.

Дополнительно: полный набор frontend-тестов — 180 успешных; production
`npm run build` — все 6 пакетов, включая стандартный Next.js Turbopack.
Полный API-набор — 135 успешных suites, 2603 успешных теста, 1 штатно пропущен.
Скриншоты содержат только искусственные данные. Полный API-прогон запускается
прямым Jest с `--runInBand`: npm-обёртка Windows не передавала этот аргумент.
Для существующих shell-тестов локально добавлен jq с проверкой SHA-256;
pipeline, npm-скрипты и системные зависимости не изменены.

Для повторения интеграции нужен отдельный локальный PostgreSQL на
`127.0.0.1:55439`, база `agency_audit` со схемой и обеими миграциями, а также
Prisma Client в `work/generated-client`. Тест намеренно отвергает другой
адрес базы. Из корня checkout запускается
`node -r ts-node/register/transpile-only apps/api/test/agency-workspace.postgres.ts`
с `TS_NODE_PROJECT=apps/api/tsconfig.json` и локальным `DATABASE_URL`.
`AGENCY_KEEP_API=1` сохраняет API на порту 55440 и локальную fixture для
`node scripts/test-agency-workspace-live.cjs`; web должен слушать 3140,
сборка использует `API_URL=http://127.0.0.1:55440/api`. Параметры
`PLAYWRIGHT_MODULE` и `CHROME_PATH` указывают на локальные runtime/browser.
Fixture с токенами остаётся только в игнорируемом `work/`, в отчёт не входит.

## Условия передачи на публикацию

Эта ветка не выполняет push, merge в master, deployment или записи в production.
Координатору необходимо отдельно проверить резервную копию, реальный preflight
дублей открытых назначений, применимость обеих миграций, генерацию Prisma,
права выбранных операторов и руководителя, действующий утверждённый скрипт.
Первый пилот должен быть ограничен явной выборкой. Описанные выше неподключённые
показатели нельзя включать под видом подтверждённых данных.

Особенности расчётов: назначенная база — уникальные агентства с назначением
до конца периода; попытки — первоначальные события по occurredAt; исправление
принадлежит исходной попытке/её автору. Доля разговоров использует уникальные
агентства с попыткой как знаменатель. Доля договорённостей — количество
разговоров оператора, а не количество агентств. Выполнение в срок — задачи
с dueAt в периоде; отменённые и без срока исключены. Просрочка — состояние
открытых задач на момент запроса. Эти правила показаны в интерфейсе/детализации.
